## Summary

Build order for the three Phase 2 stories, with per-item effort and dependencies. Phase 1 parity (`c-merchant-parity`) is not fully green — `next build` is blocked by the concurrent homepage syntax break and PNG-byte/save hands-on checks are open — so Phase 2 starts here on explicit owner override, reusing only proven contracts. If parity review later finds a regression, Phase 2 work pauses.

## Evidence

Slice status going in: six Phase 1 implementation stories done with headless verification and zero console errors; parity in-progress with two external blockers (see `2026-09-13-homepage-syntax-blocks-build.md` and the export finding in `2026-09-13-editor-design-qa-mock.md`). Reused contracts: `Template`/`Layer` in `src/editor/types.ts`, `SIZE_PRESETS`, `adaptTemplateToSize`, `TemplateRenderer`, `updateActive` draft path with revision guards, `FeedRow.source_id` product identity.

## Impact

Recommended build order (simplest merchant interaction first, no parallel edits to `src/app/editor/page.tsx` without ownership handoff):

1. `c-merchant-templates` (M) — no new backend. New module `src/editor/starterTemplates.ts` with five `build(sizeId)` starters (Product Highlight, Special Offer, New Arrival, Seasonal, Discount) using only existing layer types + bindings; new Templates rail tab with live `TemplateRenderer` thumbnails; apply replaces background+layers of the active template (keeps id/size) behind an unsaved-work confirm. Depends on: parity staying green. My Designs tab deferred (needs saved-design browsing contract).
2. `c-merchant-products-uploads` (L, split) — 2a product search/filter over the existing local `products` array (S, no contract change; insert = `selectProduct`, never mutates source rows); 2b merchant uploads (M, needs a storage/ownership decision — R2 vs local — plus remote-image security review, since tools today reuse existing assets only). Depends on: parity; 2b additionally needs the storage decision recorded before build.
3. `c-merchant-text-button-resize-preview` (XL, split) — 3a Button/CTA panel (M: text + destination URL + styling on existing badge/text layers; URL safety review); 3b Preview mode (S: chromeless route reusing `TemplateRenderer`, no save/export); 3c friendlier text (M: only what `renderStyles`/`ImageResponse` parity provably supports); 3d resize-across-formats (M: builds on placement adaptation); 3e multi-page (conditional: only with a named model contract, else wont-do). Depends on: parity; 3c on renderer-parity proof; 3e on a model investigation.

## Next action

Build item 1 now (`c-merchant-templates` → specified with implementation guidance in its story). Items 2–3 stay proposed until item 1 is verified; split sub-items become stories only when their dependency (storage decision, parity proof, model investigation) lands.
